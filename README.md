# Лабораторная работа № 1: бронирование билетов на мероприятия

Консольное приложение на Python 3.10 или новее. Внешние библиотеки не нужны.

## Запуск

Из папки проекта:

```bash
python3 main.py
```

В Windows можно использовать `python` вместо `python3`.

Для знакомства с готовыми данными выберите пункт **9**, формат `json`, путь
`data/example.json` (или формат `xml`, путь `data/example.xml`). Затем пункт **4**
покажет мероприятия, пункт **7** — бронирования. Пример содержит площадку
на 3 места, мероприятие «Джазовый вечер», клиента Анну и активную бронь на 2 билета.
Все записи имеют автоматически сгенерированные UUID.
Остаётся 1 свободное место. Цена одного билета — 1250.50 руб.

Можно создать данные с нуля: площадка → мероприятие → клиент → бронирование.
Все ID генерируются автоматически через `uuid.uuid4()` при создании объекта.
Конструкторы не принимают аргумент `id`, изменить его после создания нельзя.
Для связи объектов и отмены брони выберите нужную запись по номеру в списке:
вводить UUID вручную не требуется. Загрузчик восстанавливает сохранённые UUID4
из JSON/XML, чтобы связи оставались целыми; неверный формат ID отклоняется.

Перед выходом сохраните данные пунктом **8**. Загрузка заменяет текущие данные
только после успешной проверки всего файла. При ошибке программа возвращается
к меню, текущие данные сохраняются в памяти. Родительский каталог файла должен
существовать. Даты вводятся в формате ISO 8601, например `2027-05-20T19:00`.

## Код и диаграмма

Подробный разбор архитектуры, классов, методов и сценариев: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

- `booking/models.py` — классы Venue, Event, Customer, Booking, перечисление статусов и собственные исключения.
- `booking/service.py` — BookingSystem: создание брони, проверка мест, отмена и целостность связей.
- `booking/storage.py` — абстрактный FileStorage и реализации JsonStorage, XmlStorage.
- `main.py` — консольный интерфейс с обработкой ошибок ввода и файлов.
- `docs/classes.png` — PNG-версия UML-диаграммы.
- `docs/classes.drawio` — редактируемая UML-диаграмма, включая исключения и наследование классов хранения.
- `data/example.json`, `data/example.xml` — один и тот же набор данных в двух форматах.
- `tests/test_booking.py` — автоматические проверки.

Чтобы открыть диаграмму, перейдите в draw.io / diagrams.net, выберите
**Файл → Открыть из → Это устройство** и укажите `docs/classes.drawio`.
Названия классов и методов совпадают с Python-кодом. Прямоугольники и связи
можно редактировать отдельно.

## Правила предметной области

Площадка имеет положительную вместимость. Каждое мероприятие связано с одной
площадкой, каждая бронь — с одним мероприятием и одним клиентом. Бронь содержит
положительное целое количество билетов без нумерации мест. Сумма активных броней
не превышает вместимость площадки для соответствующего мероприятия. Отмена
освобождает места, но сохраняет запись. Повторная отмена считается ошибкой.

Деньги представлены Decimal; в файлах это строки с точностью до копеек.
Общая стоимость вычисляется как количество × цена билета в момент бронирования.
Данные сущностей неизменяемы (frozen dataclass), публичные словари доступны
только для чтения. Отмена заменяет объект брони его копией с новым статусом.

Учебная модель работает в одном процессе. Она не учитывает оплату, отдельные
места, пересечения расписаний площадки и срок истечения брони. Даты мероприятий
не ограничены текущей датой: можно хранить архивные события.

## Структура файлов

JSON содержит `version: 1` и массивы `venues`, `events`, `customers`, `bookings`.
XML использует корень `<booking_system version="1">` и одноимённые контейнеры;
внутри — элементы `venue`, `event`, `customer`, `booking` с полями-дочерними
элементами. Идентификаторы — строки UUID4, ссылки содержат UUID связанных объектов; `capacity` и `quantity` — целые;
даты — ISO 8601; `price` и `unit_price` — строки Decimal; статус — `active`
или `cancelled`. Поля объектов показаны в примерах и UML.

Оба формата загружаются через общую проверку: обязательные поля, типы, версия,
уникальность ID, существование ссылок и доступность мест. Повреждённые данные
вызывают StorageError. Сохранение использует временный файл и замену целевого
файла после успешной записи.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Проверяются суммы и свободные места, переполнение, отмена, неверный ввод,
дубликаты ID, отсутствующие ссылки, ошибки файлов и схемы, восстановление
данных в обоих форматах и продолжение работы меню после ошибки.
